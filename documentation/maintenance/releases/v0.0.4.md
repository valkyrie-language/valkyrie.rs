> 本页记录该发布时的历史行为，不定义现行编译架构。当时以 `.nyar` 命名的 OVM 执行字节码对应现行 OdinVM 的 `.odin` 执行产物，与现行 `.nyar` 程序集不是同一产物合同。

## ✨ Features

- `legion` 当时默认启用 OVM/Odin 执行 lane：可对历史 `.nyar` 执行字节码做构建与运行，并把工作负载意图标志传入当时的 VM runtime。
- 无 `entry` 的 library 工程在 `legion build --target` 时合成构建目标，便于外部产物基准与库模式包。
- `vcc` 宿主在可用时走原生 N-API：支持 `legion` CLI argv / stdio 捕获，以及测试侧的 `spawnNativeLegion` 与 当时的 OVM 执行入口辅助。
- OVM/Odin 执行字节码侧补充可观察能力：`CallIntrinsic`、`CallImport`（替代 `CallNative`）、`ObjectNew` / `FieldGet` / `FieldSet` 与 layouts，以及执行清单中的合同版本字段。

## 🐛 Bug Fixes

- 当时 OVM 执行 lane 的 `legion run` 占位路径改用逻辑入口，避免错误入口名。
- 语义缓存在还原 MIR 未通过 `validate_module` 时拒绝复用，避免陈旧缓存导致错误产物。
